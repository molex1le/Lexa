# Задача: Android-приложение для пополнения английского словаря

Ты – ведущий Android-разработчик и продуктовый дизайнер в одном лице. Строим с нуля приложение
на Kotlin + Jetpack Compose. Рабочее название – «Lexa» (можно предложить своё).
Язык интерфейса – русский, изучаемый язык – английский.

Работай по фазам ниже. После каждой фазы останавливайся, показывай результат
(скриншоты экранов, список сделанного) и жди моего «ок». Не делай всё одним заходом.

## 1. Продукт

### Ядро – флешкарточки с вводом ответа
- На карточке показано английское слово (или русский перевод, направление переключается в настройках).
- Я **вписываю** ответ с клавиатуры, а не просто переворачиваю карточку.
- Проверка ответа прощает мелочи: регистр, лишние пробелы, ё/е, частица «to» у глаголов,
  одна опечатка в словах длиннее 5 букв (расстояние Левенштейна ≤ 1). Если у слова несколько
  переводов, засчитывается любой.
- Неверно – показываем правильный ответ и пример, слово **улетает обратно в «Новые слова»**
  и снова попадает в ближайшие сессии.
- Верно – слово поднимается по коробкам Лейтнера (1 → 2 → 3 → 4 → 5, интервалы
  0 / 1 / 3 / 7 / 21 день). После 5-й коробки слово считается выученным.
- Кнопка «Я знал, это опечатка» – засчитать ответ вручную.

### Списки
- **Новые слова** – всё, что ещё не выучено, включая только что переведённые слова и те,
  на которых я ошибся. Именно отсюда собирается сессия.
- **Избранное** – любимые слова, отмечаются звёздочкой на карточке слова, в переводчике и в списках.
  Избранное не зависит от статуса изучения.
- **Выученные** – архив, с возможностью вернуть слово в изучение.
- Поиск, сортировка (по дате добавления, по алфавиту, по числу ошибок), удаление свайпом с отменой.

### Статистика
Отдельный экран (и короткая сводка на главном):
- сколько слов выучено всего, сколько в изучении, сколько новых;
- **какие** слова выучены – список с датой, когда слово ушло из 5-й коробки, с переходом в карточку слова;
- выучено за сегодня / неделю / месяц и график по дням (столбики за последние 30 дней);
- серия дней подряд (streak) и лучшая серия;
- точность ответов (% верных) за неделю и за всё время;
- «трудные слова» – топ по числу ошибок, с кнопкой «Повторить их сейчас»;
- распределение слов по коробкам Лейтнера 1–5.
Всё считается из `ReviewLog` и `Word` запросами Room (Flow), без отдельных счётчиков, которые могут разойтись с данными.
Правила графиков: одна серия – без легенды, сетка 3–5 бледных линий или никакой, акцентный цвет (маркер)
только на главных данных – сегодняшний столбик или текущий период; цифры – крупной типографикой, не плитками с иконками.
Пустая статистика честная: ноль печатается как 0, а не прячется, рамка блока остаётся.

### Главная фича – встроенный переводчик
- Поле ввода: вставляю незнакомое слово (или короткую фразу) и получаю:
  - перевод(ы) на русский по частям речи;
  - транскрипцию (IPA) и кнопку произношения (аудио из словаря, если есть, иначе Android TextToSpeech, en-US/en-GB);
  - синонимы (кликабельные: тап открывает перевод синонима);
  - 2–3 примера употребления с переводом;
  - короткое определение на английском.
- Каждое переведённое слово **автоматически добавляется в «Новые слова»** (тост «Добавлено в новые слова» с кнопкой «Отменить»).
  Повторный перевод того же слова не создаёт дубль.
- История переводов.
- Приложение доступно в системном меню выделения текста (`ACTION_PROCESS_TEXT`) и в «Поделиться»:
  выделил слово в браузере – «Перевести в Lexa» – слово уже в списке.

### Источники данных переводчика
Спроектируй `DictionaryRepository` с интерфейсом и несколькими реализациями, чтобы источник
можно было заменить без переписывания UI. Перед выбором **проверь актуальное состояние
и лимиты API в интернете** и предложи мне вариант. Отправная точка:
- перевод EN→RU – Google ML Kit Translation (на устройстве, бесплатно, работает офлайн после загрузки модели);
- транскрипция, аудио, синонимы, примеры, определения – Free Dictionary API (dictionaryapi.dev);
- запасной вариант для богатых данных – LLM API за флагом, ключ только в `local.properties`, не в репозитории.
Все ответы кэшируются в Room: повторный перевод работает без сети.

## 2. Стек и архитектура
- Kotlin, Jetpack Compose, Material 3 как основа, но **с полностью своей темой** (не дефолтная фиолетовая).
- Слои `data` / `domain` / `ui`, MVVM + однонаправленный поток данных (StateFlow, одно `UiState` на экран).
- Hilt для DI, Room для БД, DataStore для настроек, Ktor или Retrofit + kotlinx.serialization,
  Navigation Compose с type-safe маршрутами, Coroutines/Flow.
- minSdk 26, targetSdk – последний стабильный. Gradle version catalog (`libs.versions.toml`).
- Модель данных минимум: `Word` (term, translations, ipa, audioUrl, examples, synonyms, isFavorite,
  box, nextReviewAt, mistakesCount, addedAt, source), `ReviewLog`, `TranslationCache`.
- Анимации: Compose Animation API (`animate*AsState`, `AnimatedContent`, `updateTransition`, `Animatable`,
  shared element transitions) – основа. Для сложных иллюстрированных моментов – Lottie (`lottie-compose`)
  или Rive (`rive-android`), например празднование выученного слова или рекорда серии.
  anime.js – веб-библиотека и в нативном Compose не работает; не тащи WebView ради анимаций.
- Графики статистики – Vico (`com.patrykandpatrick.vico:compose-m3`) или свои Canvas-графики, если Vico мешает
  соблюсти правила дизайна. Проверь актуальную версию.
- Тесты: юнит-тесты на проверку ответа (опечатки, ё/е, несколько переводов) и на логику коробок –
  это сердце приложения, покрытие обязательное. Скриншот-тесты Compose через Roborazzi для каждого экрана
  в светлой и тёмной теме.
- Разработка на MacBook Air M4: Android SDK уже стоит (`~/.android`, `~/.gradle`), проверь версии сам.

## 3. Дизайн

Перед кодом UI загрузи скиллы проекта из `.claude/skills/`: `frontend-design` и `design-taste-frontend`
(для приложения – её раздел `references/app-screens.md`, а не веб-раздел).
Скрипты taste-скилла (`draw.mjs`, `inspect.mjs`) рассчитаны на HTML и здесь не используются –
правила переносим вручную, проверка – скриншотами.

### Идея из предмета
Неизвестное слово в тексте выделяют маркером. Это и есть идея: **жёлтый маркер – единственный акцент**
приложения. Им отмечено новое слово, им подсвечено то, что надо сделать сейчас. Всё остальное – чернила на бумаге.
Сначала напиши план токенов (4–6 цветов hex, шрифты и роли, сетка, принципы) и проверь его
вопросом «получилось бы то же самое у любого другого приложения со словами?» – если да, переделай.

### Типографика
- Слово на карточке – главный элемент экрана: очень крупно (48–64sp), шрифт с характером
  (например, словарная антиква вроде Literata или Newsreader – выбери и обоснуй), трекинг слегка отрицательный.
- Интерфейс – один гротеск. Не больше двух семейств и пяти размеров на всё приложение.
- Транскрипция – шрифтом интерфейса, не моноширинным.

### Правила (из taste и frontend-design, адаптировано под Compose)
- Один фон, одни чернила, один акцент. Цвет – на смысле (новое слово, ошибка, правильно), а не на хроме.
- Нельзя: градиенты, glassmorphism и blur, свечения, тени у элементов в покое (тень только у всплывающего –
  bottom sheet, диалог), фиолетовый и индиго, кремовый фон с терракотой, эмодзи, мелкие подписи капслоком
  над заголовками, нумерация 01/02/03, иконки в цветных кружках, одинаковые сетки карточек,
  выделение одного слова в заголовке другим цветом или курсивом.
- Поверхности разделяются шагом тона, а не рамкой и не тенью.
- Скругления: выбери одно правило и держи его везде.
- Статистика – это типографика (крупная цифра + подпись), а не плитка с иконкой.
- Пустые состояния – призыв к действию словами пользователя («Пока пусто. Переведи первое слово –
  оно появится здесь»), ошибки объясняют, что случилось и что делать, без извинений.
- Кнопки названы действием: «Проверить», «Добавить в избранное», и тот же глагол в подтверждении.
- Движение – живое, но со смыслом, каждое отвечает на действие или показывает, что изменилось:
  - переворот карточки (3D-поворот через `graphicsLayer`, пружина);
  - «улёт» слова при ошибке – карточка уезжает в сторону вкладки «Новые» и вкладка коротко пульсирует;
  - верный ответ – слово «переезжает» в следующую коробку, лёгкая отдача (spring);
  - отметка маркером при добавлении слова из переводчика – жёлтая полоса прорисовывается под словом слева направо;
  - статистика: цифры досчитывают от 0 до значения, столбики графика вырастают по очереди со сдвигом 40–60 мс;
  - выучил слово (ушло из 5-й коробки) или побил рекорд серии – один короткий момент празднования (Lottie/Rive), не чаще раза за сессию;
  - тактильный отклик (`HapticFeedback`) на верный и неверный ответ.
  Только transform и opacity, без смены вёрстки на лету. Длительности 150–400 мс, пружины вместо линейных кривых.
  Без анимаций «просто так»: ничего не мерцает и не крутится в покое.
  При системной настройке «Убрать анимацию» – мгновенные переходы, контент не теряется.
- Доступность: touch-target ≥ 48dp, контраст по WCAG AA, contentDescription у всех иконок,
  работа с TalkBack, крупный системный шрифт не ломает вёрстку.
- Тёмная тема – отдельная продуманная палитра, не инверсия.

### Цикл «посмотри и поправь»
После каждого экрана: прогони Roborazzi (светлая и тёмная тема, обычный и крупный шрифт, узкий экран 360dp),
открой картинки, разбери их по `references/critique.md` из taste-скилла, исправь три главные проблемы,
повтори. Максимум три круга. Судишь только по картинке: если проблема видна на скриншоте – она реальна.

## 4. Агенты и скиллы
Агенты лежат в `.claude/agents/` (из коллекции agency-agents). Вызывай их по имени из frontmatter:

- **Software Architect** – фаза 0: структура модулей, модель данных, DI, навигация, ADR на выбор

- **Mobile App Builder** – основной исполнитель: Kotlin, Compose, Room, Hilt, интеграции

- **UI Designer** – план токенов, тема Compose, вёрстка экранов, цикл скриншотов Roborazzi.

  Правила раздела 3 этого файла важнее его собственных привычек: если агент тянется к градиентам,
  теням или фиолетовому – это ошибка.
- **Test Automation Engineer** – юнит-тесты проверки ответа и коробок Лейтнера, скриншот-тесты.
- **UI Finish-Gate Reviewer** – в конце каждой фазы с UI: смотрит только на скриншоты и ищет
  шаблонный, взаимозаменяемый интерфейс.
- **Code Reviewer** – в конце каждой фазы, на свежую голову: не видел процесс написания кода,
  проверяет diff (утечки корутин, лишние рекомпозиции, хардкод цветов вне темы, ключи в репозитории).
- **Accessibility Auditor** – фаза 6: TalkBack, контраст, touch-target, крупный шрифт.
- **Reality Checker** – последний шаг фазы 6: не принимает «готово» без доказательств

## 5. Фазы
0. План: архитектура, модель данных, выбор API (ADR), план токенов дизайна. Жди моего «ок».
1. Скелет проекта, тема, навигация, Room, пустые экраны с пустыми состояниями.
2. Переводчик: репозиторий, кэш, экран результата, произношение, авто-добавление в «Новые».
3. Тренировка: ввод ответа, проверка, коробки Лейтнера, «улёт» в новые слова.
4. Списки и статистика: новые, избранное, выученные; поиск, сортировка, свайпы; экран статистики с графиками.
5. Интеграции: меню выделения текста и «Поделиться», напоминание о повторении (WorkManager + уведомление).
6. Полировка: движение (Compose Animation, Lottie/Rive), тактильный отклик, доступность, тёмная тема, финальный review.
