# ADR-0001: Источники данных для переводчика

## Статус
Предложено (фаза 0, 29.10.2026). Ждёт решения владельца.

## Контекст

Переводчик – главная фича Lexa. На одно введённое слово (или короткую фразу) экран должен показать:

1. переводы на русский **по частям речи**;
2. транскрипцию (IPA) и произношение (аудио из словаря, иначе Android TextToSpeech);
3. кликабельные синонимы;
4. 2–3 примера употребления **с переводом**;
5. короткое определение на английском.

Ограничения из спецификации и железа:
- результат кэшируется в Room, повторный перевод работает без сети;
- источник заменяется без переписывания UI (`DictionaryRepository` с интерфейсом и несколькими реализациями);
- LLM – только за флагом, ключ только в `local.properties`;
- личный проект, бюджет нулевой; на машине разработчика нет эмулятора, проверка UI – скриншотами Robolectric/Roborazzi.

Главная проблема, из-за которой нужен этот ADR: **ни один бесплатный источник не даёт всё сразу.**
- Free Dictionary API (dictionaryapi.dev) – части речи, определения, примеры, синонимы, IPA, mp3, но всё только на английском.
- ML Kit Translation – переводит строки, а не словарные статьи: на `run` вернёт одно «бежать», без разбиения на сущ./глаг.
- Готовые EN→RU словари с частями речи (Яндекс.Словарь) запрещают хранить данные.

## Варианты

### A. Только ML Kit + Free Dictionary (отправная точка из спецификации)
- Плюс: бесплатно, без ключей, перевод работает офлайн.
- Минус: нет переводов по частям речи и нет перевода примеров. Пункты 1 и 4 не выполняются.

### B. Композит из бесплатных источников + машинный перевод «по кусочкам» (рекомендуется)
Данные собираются из нескольких источников, недостающее ML Kit переводит частями (подробно ниже).
- Плюс: бесплатно, без ключей; все пять пунктов закрыты; каждый источник заменяется отдельно.
- Минус: переводы по частям речи – эвристика, качество «как у офлайн Google Translate»; три сетевых источника вместо одного; надо аккуратно обрабатывать частичные ответы.

### C. Яндекс.Словарь как основной источник
- Плюс: лучшее качество EN→RU по частям речи «из коробки».
- Минус: нельзя хранить данные (противоречит `Word` в Room и офлайн-кэшу), обязательная атрибуция на каждом экране, выдача ключей не подтверждена, зависимость от одного провайдера.

### D. LLM (Claude Haiku 5.5) как основной источник
- Плюс: лучшее качество и полнота, особенно на фразах и многозначных словах.
- Минус: платно, нужен ключ, ключ извлекается из APK, офлайн не работает (кроме кэша), возможны галлюцинации в IPA.

### E. Свой офлайн-словарь из Wiktextract
- Плюс: офлайн, бесплатно, переводы по значениям от людей.
- Минус: отдельный пайплайн сборки (24,8 ГБ сырых данных), неполное покрытие русского, размер приложения растёт. Слишком дорого для MVP.

## Решение (предлагаемое)

**Вариант B по умолчанию, D – как флаг «Богатый перевод», E – отложить в ADR-0002.** Яндекс не используем.

### Источники и их роли

| Поле экрана | Основной источник | Запасной |
|---|---|---|
| Транскрипция IPA | Free Dictionary `phonetic` / `phonetics[].text` | Claude (если флаг) |
| Аудио | Free Dictionary mp3 (предпочитаем `-us`, потом `-uk`/`-au`, по настройке акцента) | Android TextToSpeech `en-US`/`en-GB` |
| Части речи + определения EN | Free Dictionary `meanings` | Claude |
| Переводы по частям речи | ML Kit, перевод с подсказкой части речи (см. ниже) | Claude |
| Синонимы | Free Dictionary `synonyms` (уровень значения + уровень части речи) | Datamuse `rel_syn` |
| Примеры с переводом | Tatoeba (перевод сделан людьми) | Примеры Free Dictionary, переведённые ML Kit, с пометкой «машинный перевод» |
| Фраза (FD не нашёл) | ML Kit – перевод целиком + Tatoeba | Claude |

### Как получить «переводы по частям речи» и «примеры с переводом»

1. **Перевод с подсказкой части речи.** Для каждой части речи из ответа Free Dictionary ML Kit переводит короткую строку-«рамку», которая заставляет модель выбрать нужную форму:
   - verb → `to {term}` (`to run` → «бежать»; частицу «чтобы», если появится, срезаем);
   - noun → `a {term}` (`a run` → «пробег»; артиклей в русском нет, они пропадают сами);
   - adjective, adverb и прочее → `{term}` без рамки.
   Результат нормализуем (нижний регистр, без точки в конце), дубли между частями речи убираем.
2. **Русская подпись к значению.** Первое определение каждой части речи (обычно короче 15 слов) переводим ML Kit и показываем мелко под переводом как «смысл». Это разводит значения многозначных слов (`run` – бег / управлять).
3. **Примеры.** Сначала Tatoeba: 2–3 пары, где английское предложение содержит слово, с переводом от людей. Если пар меньше двух – добираем примерами Free Dictionary и переводим каждый через ML Kit, помечаем `ExampleSource.MACHINE`.
4. **Флаг «Богатый перевод»** (Claude Haiku 5.5). Включается, только если ключ есть в сборке и пользователь включил его в настройках. Вызывается, когда (а) Free Dictionary ничего не нашёл (фраза, сленг), или (б) в режиме «всегда» в настройках. Ответ – JSON по схеме `DictionaryEntry` (structured output), проходит ту же валидацию, что и остальные источники.

ML Kit на один перевод: до ~12 вызовов на устройстве (1 заголовок + ≤4 части речи + ≤4 определения + ≤3 примера), каждый – десятки миллисекунд. Вызовы последовательные, через один синглтон `Translator`.

### Поведение при сбоях
- Каждый сетевой источник – свой таймаут (4 с) и `runCatching`; результат собирается из того, что пришло (частичный результат лучше ошибки).
- Free Dictionary 404 и 502 на неизвестное слово считаем «не найдено»; негативный кэш на 24 часа.
- Модель ML Kit не скачана и сети нет – показываем словарные данные (если есть в кэше) и текст: «Перевод появится, когда скачается русская модель (~30 МБ). Подключись к Wi-Fi или разреши загрузку по мобильной сети в настройках».
- 429 от Free Dictionary – повтор не раньше `x-ratelimit-reset`, пока – данные из кэша.

### Кэш
`TranslationCache` хранит **ответ каждого источника отдельно** (ключ – нормализованный запрос + id источника + версия схемы) и собранную статью. Зачем раздельно: можно заменить один источник или включить флаг LLM и дозапросить только недостающее. Схема таблиц – в `docs/ARCHITECTURE.md`.

### Атрибуция
Экран «Настройки → Источники данных»: Wiktionary (CC BY-SA, через dictionaryapi.dev), Tatoeba (CC BY 2.0 FR), Google ML Kit, Datamuse; Claude – если флаг включён. У примера из Tatoeba – маленькая подпись «Tatoeba».

## Последствия

Становится проще:
- всё бесплатно, без ключей и регистрации; основной перевод работает офлайн;
- любой источник меняется одной реализацией `DictionarySource` + строкой в Hilt-модуле, UI не трогаем;
- LLM подключается флагом, без изменений в UI и модели данных.

Становится сложнее / чем платим:
- переводы по частям речи – эвристика машинного перевода: на редких и многозначных словах будут промахи («run» как noun может дать «пробег», а не «забег»). Поэтому в карточке слова переводы **редактируемые** (это ещё и подстраховка для проверки ответа);
- три внешних сервиса без SLA (FD, Tatoeba, Datamuse) – волонтёрские. Смягчение: кэш, частичные результаты, замена через интерфейс;
- ML Kit нельзя проверить в Robolectric: для реального перевода и загрузки модели нужен телефон или эмулятор с Google Play (сейчас на машине ни того, ни другого);
- первая загрузка модели – ~30 МБ, по умолчанию только по Wi-Fi.

Решение владельца на фазе 2 (29.10.2026): флага Claude/LLM и Datamuse в MVP нет – источники только Free Dictionary, ML Kit (модель качается по любой сети) и Tatoeba.

## Что нужно решить владельцу
1. Утвердить вариант B (+ D за флагом).
2. Нужен ли флаг Claude вообще в MVP (тогда положить ключ в `local.properties` как `CLAUDE_API_KEY=…`), или отложить до фазы 6.
3. Режим флага: «только когда бесплатные источники не справились» (рекомендую) или «всегда».
4. Как будем проверять ML Kit и TTS: подключить телефон по `adb` (рекомендую) или поставить образ эмулятора `system-images;android-37.0;google_apis_playstore;arm64-v8a` (~2 ГБ).
